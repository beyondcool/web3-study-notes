> 源码范围：`/home/zh/workspace/perp-backend`
> 配套篇：《Perpetual 永续合约项目拆解与源码学习指南》（Solidity 篇，17 章）

## 阅读说明

本指南是 Solidity 篇的**配套服务端篇**，不重复讲解 `paper` / `credit` 记账、EIP-712 域构造、资金费率累计值语义、清算公式等合约侧内容——这些已在 Solidity 篇中展开，本指南在各章末尾以「对照 Solidity 篇第 N 章」的形式给出索引。

两者的分工是：

| | Solidity 篇 | 本指南（Go 篇） |
|---|---|---|
| 关注点 | 链上账本的**真相与验证** | 链下服务的**撮合与运营** |
| 核心问题 | 状态怎么存、操作怎么验、风险怎么算 | 订单怎么撮合、价格怎么来、任务怎么跑 |
| 阅读方式 | 追一条记账链路 | 追一笔订单的生命周期 |

**阅读建议**：不必按章节顺序通读。第三部分（第 7~12 章）是本指南的重心，它追踪一笔订单从 HTTP 请求到链上成交的完整一生；其余部分是这条主线的上下游支撑。如果时间有限，推荐顺序为 **第 1 章 → 第 3 章 → 第 7~12 章 → 按需查阅其余章节**。

## 目录

### 第一部分：视角切换

- **第 1 章：从合约到服务端 — 合约不管的那些事，正是这个 Go 后端存在的理由**
  - *核心学习目标*：站在服务端视角重新理解"链下撮合 + 链上结算"的分工边界——合约只负责记账与验证，而撮合、喂价、定时任务、用户体验这四件事全部落在 Go 侧，从而建立起"为什么需要这个后端"的整体认知。（对照 Solidity 篇第 2、3 章）

- **第 2 章：代码地图 — 五千行 Go 代码的目录职责与推荐阅读顺序**
  - *核心学习目标*：建立全局导航能力，掌握 `internal/` 下 13 个子包（`handler` / `logic` / `model` / `engine` / `chain` / `listener` / `svc` / `config` …）各自的职责边界，并区分哪些是 goctl 自动生成的样板代码、哪些是需要精读的核心逻辑。

- **第 3 章：先跑起来 — main 函数的启动序、依赖装配与"无链降级"设计**
  - *核心学习目标*：逐行读懂 `metanode.go` 里六大组件的启动顺序与相互引用关系，理解 `Chain == nil` 时服务仍能提供 HTTP 查询的降级设计——这是本项目最值得初学者体会的工程决策，也是你本地验证代码的前提。

### 第二部分：请求入口

- **第 4 章：go-zero 约定式工程 — metanode.api 如何"生"出 handler、types 与路由**
  - *核心学习目标*：理解声明式 API 定义文件与生成代码之间的对应关系，看懂 `metanode.api` 中的 `type` 与 `@server` 路由声明如何映射为 `internal/types/`、`internal/handler/` 和最终的服务路由表，从而不再被自动生成的样板代码干扰。

- **第 5 章：服务枢纽 ServiceContext — 依赖注入、接口抽象与 nil 安全**
  - *核心学习目标*：理解 `ServiceContext` 作为唯一依赖容器的设计意图，重点掌握它用三个小接口（`MatchBookSink` / `OrderBookSource` / `IndexPriceSource`）打破「撮合引擎与 svc 包互相引用」循环依赖的技巧，以及 `Chain != nil` 判空如何贯穿所有业务逻辑。

- **第 6 章：钱包即身份 — EIP-191 登录、Redis nonce 与 JWT 签发**
  - *核心学习目标*：掌握 Web3 应用最常见的登录范式：服务端下发 nonce → 用户用钱包对明文消息签名 → 服务端恢复地址完成认证，并理解 nonce 的一次性消费与 JWT 的有效期设计。（与第 7 章的 EIP-712 签名形成"身份签名 vs 交易签名"的对比）

### 第三部分：撮合主线 — 一笔订单的一生

- **第 7 章：下单接口 — 从 HTTP 请求到 orderId，Go 侧如何复现合约的订单哈希**
  - *核心学习目标*：读懂 `CreateOrder` 的业务校验链路（过期时间 → 字段解析 → 签名验证 → 防重放），并理解为什么 `orderId` 直接取自 EIP-712 digest——它必须与合约中用于累计成交量的 `orderHash` 完全一致，链上链下才能对上账。（对照 Solidity 篇第 6、7 章）

- **第 8 章：内存订单簿 — OrderBook 的数据结构与价格时间优先的排序实现**
  - *核心学习目标*：看懂订单簿为何用两个切片而非树结构、买卖两侧的排序方向为何相反，以及 `paperAmount` 的正负号如何同时承担"多空方向"和"归入哪一侧"两个语义。（对照 Solidity 篇第 6 章理解 paper 的符号约定）

- **第 9 章：撮合循环 — match() 的循环条件、remain 余额簿与过期单剪枝**
  - *核心学习目标*：追踪 `match()` 的完整循环逻辑——价格交叉判定、`remain` 余额簿如何支持部分成交、队首过期单为何必须剪枝，以及本项目"买单为 taker、卖单为 maker"这一简化假设与合约通用撮合模型的关系。（对照 Solidity 篇第 8 章的 `_matchOrders`）

- **第 10 章：成交上链 — tradeData 的 ABI 编码、费率打包与批量提交**
  - *核心学习目标*：掌握链下撮合结果如何被打包成合约能解码的 `tradeData`——`(Order[], bytes[], uint256[])` 三元组的编码要求、maker/taker 费率如何压进 `info` 字段、以及批量提交的收集与切片策略。（对照 Solidity 篇第 8 章的 `approveTrade` 校验顺序）

- **第 11 章：链上失败之后 — rollbackMatch 的边界，以及它没有覆盖的部分**
  - *核心学习目标*：理解"链上成功才更新数据库"这一保守策略的动机与代价，重点看清 `rollbackMatch` 只回滚内存订单簿和 `remain`、并不回滚数据库字段的边界；进而思考：当上链成功但进程在写库前崩溃时，会发生什么。

- **第 12 章：重启恢复 — RestorePendingOrders 如何从数据库重建内存簿**
  - *核心学习目标*：读懂服务重启时如何用 `filled_amount` 与订单原始数量之差重建 `remain`，并理解这一恢复机制与第 11 章残留问题的关联——读库恢复的数据，正是上一次崩溃可能没写准的那份数据。

### 第四部分：链交互与后台服务

- **第 13 章：chain.Client — 手写最小 ABI、只读视图封装与发交易的 gas/nonce**
  - *核心学习目标*：理解本项目为何不用 `abigen` 生成完整绑定、而是手写最小 ABI 片段，掌握 `callDealer` / `callPerp` 两个只读调用封装与 `SubmitPerpTrade` 的签名交易构造流程，建立"链上交互层"的心智模型。（对照 Solidity 篇第 15 章的 `MetaNodeView` 只读函数）

- **第 14 章：资金费率结算 — FundingRateKeeper 的定时循环与 delta 计算**
  - *核心学习目标*：阅读一个完整定时任务的标准写法（ticker 循环 + stopCh 优雅退出），并理解溢价 delta 的计算、上限裁剪与批量上链，看清 keeper 只是"推送预先算好的累计值"、合约不做任何费率计算这一分工。（对照 Solidity 篇第 10 章）

- **第 15 章：指数价喂价 — CoinbaseFeed 的 WS 订阅、重连与降级**
  - *核心学习目标*：掌握一个外部行情源接入的完整工程考量：WebSocket 订阅、断线重连、写库节流、以及取不到链上 Chainlink 价格时如何降级回标记价，理解"指数价 → 资金费率"这条数据链路的源头。（对照 Solidity 篇第 13 章）

- **第 16 章：扫链入账 — TreasuryDepositWatcher 的游标、确认数与幂等**
  - *核心学习目标*：阅读本项目唯一一个真正工作的链上事件监听器，掌握扫块游标（Redis 记录 + 数据库兜底）、确认数等待、重启后回溯范围这几个链下索引器的通用要素，并理解幂等入账为何必须靠唯一约束而非应用层判断。

- **第 17 章：清算机器人 — 一个未完成模块的解剖**
  - *核心学习目标*：读懂 `liquidator.go` 的骨架设计（检查循环、仓位遍历、执行入口），并明确识别其中的占位实现——`checkSafeOnChain` 直接返回 `true`、`executeLiquidation` 整段被注释；这一章的价值在于对照合约侧的完整清算能力，思考一个生产级清算机器人"本该怎么做"。（对照 Solidity 篇第 12 章）

### 第五部分：数据与接口

- **第 18 章：数据访问层 — 12 个 Model 与 sqlx/GORM 双实现**
  - *核心学习目标*：理解 `internal/model/` 下为何同时存在 go-zero `sqlx` 与 GORM 两套数据访问写法，掌握"哪些表必须走 GORM"这一约束的由来（`sqlx` 的 `?` 占位符与 pgx 驱动不兼容），并学会读数据库迁移代码。

- **第 19 章：查询接口 — 直接读链 vs 读库，以及链上/链下双账本现实**
  - *核心学习目标*：对比两类查询接口的取数来源——仓位与风险直接调 `Dealer` 视图函数、订单与成交读数据库，理解这种"能读链就读链"策略的取舍；并认识本项目同时存在链上 `credit` 与链下 `ledger_balances` 两本账的现实，思考一致性由谁保证。

- **第 20 章：现状盘点 — 哪些能跑、哪些是占位、这套代码教了什么**
  - *核心学习目标*：在读完代码之后做一次全局复盘：梳理各类 `TODO` 与占位实现的完整清单，评估项目的实际完成度与可运行边界，并把本项目的工程模式（约定式代码生成、接口打破循环依赖、链上链下一致性策略、降级设计）提炼为可迁移到其他项目的经验。
